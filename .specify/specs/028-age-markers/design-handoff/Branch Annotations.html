One primitive: the detour

Model

Your call — sub-branch and fork are the same thing. Both are a detour that opens and closes inside one age section.

Definition

A branch is a run of steps opened by a marker, plus a condition. It lives inside the same ordered item list you already have — one new item kind, kind:'branch', wrapping child items.

Rejoin is positional: the branch ends at its closing marker and the next step is common again. No pointer, nothing to dangle. A fork is just a branch whose closing marker sits at the end of the final section.

Timings

Branch steps carry their own times; the main line is untouched. Nothing after the split is re-timed: the common steps keep the times the author wrote.

Conditions

Two inputs per path. A short title, plain text, which is what the graph legend, the focus-mode bar and the collapsed row can show. And a description — the same rich field as a step note, :: autocomplete and icon picker included — which carries the real condition. Matchups need no field of their own: the icon set already has every civ, so a matchup is just an icon in the description.

If a civ icon should later drive matchup filtering, it can be read back out of the description tokens — still no extra field.

When there is no main line

A branch is really a split with N paths, and each path carries a short title plus its description — the title is what the graph legend, the focus bar and the collapsed row can actually show. No path is the main line by default; nobody declares one when writing a build down.

An author who does want a reference line sets a main boolean on one path. That path then reads as the build and the others render as collapsed detours. Untouched, the paths are equal, render as a pick-one control, and nothing collapses — because there is nothing to fall back to.

Same data, one boolean apart — the reading control is the only difference. See the frame on the right.

Colour

Gold is already spoken for — ages, timings and primary actions. So alternatives use secondary, the brand's other colour (#294790), for every rail, marker and pick control. Not a new hue: one token set derived from the theme value, --sec, --sec-soft, --sec-border, --sec-text, plus three fills and an on-colour.

The branch mark follows one rule: --sec on any neutral surface, and inherit only where it sits on a filled branch surface — a selected path chip, the focus-mode path bar — where blue on blue would vanish. Disabled menu entries grey out whole, mark included.

It reads as a deliberate second axis rather than an accident: gold means "where you are in the build", blue means "which way you went". That is also why the pick control is not the default gold button — a gold button beside a gold age plate would say the two are the same kind of thing.

Default state of the steps view

Collapsed by default. The main line reads exactly as it does today; a branch appears as one slim condition row under its parent step. Expanding it opens the lane in place.

  • Nothing regresses. Builds without branches look identical; builds with them gain one 28px row.
  • The condition is the headline, not the steps. A reader scanning for "what do I do if…" reads triggers, not 4 extra rows of vil counts.
  • Caps at 1–2 per build without the list ever looking like a tree.

Authoring

Two markers bracket the alternatives, the way an age-up and its "reached" plate already bracket a lane. Both are inserted from one menu on the insert line and both stay inside one age section, so the paths can rejoin onto a common step before the age-up. Steps belong to a path by sitting between the markers. No dragging.

Rejoin

Implicit in the data, explicit in the UI. The closing marker sets the end; it is an item in the list, not a pointer, so there is no "rejoin" object to keep in sync. The reading view needs no cap for it — the lane simply ends and the next step is unindented again.

Why it stays one feature

The reader sees a different control, but the author is doing the same thing: a split, two paths, a rejoin. The only difference is whether a path carries the main flag. In the editor that is a single "this is the main line" toggle — set it and the other path collapses into the detour row from the frame on the left.

  • Titles only in the row. Two short titles fit the table's row height and stay readable; the full condition is a tooltip, and it is spelled out in the first step of each path. Truncating conditions to an ellipsis would hide the knowledge the feature exists to carry.
  • Never pre-answered. A path is highlighted so the table has content, but the control sits above it unanswered until tapped — the reader is told a decision exists before they read numbers.
  • Graph: one path at a time, named in the legend and in sync with the step list — overlaying every resource series twice is unreadable.
  • Focus mode: the decision cannot be dismissed. No "carry on" option, and a countdown falls back to the first path so the clock never stalls.
  • Three or more paths stack the pick-one control vertically instead of side by side. Beyond three, that is two builds, not one.

Your four questions

How do you start one? The insert line's + becomes a small menu instead of a single "Step" pill — Step, Note, Age up, Alternatives. Picking Alternatives inserts the whole bracket at once: an opening marker, one path with an empty step, and a closing marker. Nothing is dragged and nothing is left dangling.

How do you close one? The closing marker arrives with the block, so closing is never a separate act — but it is a real item, because the paths can rejoin before the age-up and usually should. Move it by inserting steps: above the marker they belong to the active path, below it they are common to both. Deleting either marker removes the bracket and lifts every path's steps back into the section.

A second alternative in the same timeframe? That is the + Add alternative tab in the path bar. Paths are siblings inside one bracket, so a second one shares the same two markers and needs no new ones. Editing shows one path at a time — the tabs switch which path's steps the table is showing, the same control the reader gets.

What does the menu look like inside an alternative? Your guess, and no Close entry — the merge line is always there, so closing is never something you add. Step and Note stay; Age up and Alternatives grey out rather than vanishing, with the reason in the standard tooltip, so the constraint is learnable instead of mysterious. Where you click decides membership: above the merge line the step joins the active path, below it the step is common to both.

Different step types in the add menu? Yes, and that is the whole change to the add affordance: one menu with four entries instead of a "Step" pill plus a separate "Add age-up" button at the bottom. That bottom button is why the old sketch was confusing — it is gone, and age-up now lives in the same menu as everything else.

  • Drag and drop is deliberately out of scope. The markers make ordering an insert-and-delete problem, so reordering can arrive later without changing the data.
  • The main-line toggle lives on the path bar as "Set as main" — flag one path and the reader gets the collapsed detour view instead of the pick-one control.
  • One phase only. Age up is greyed out in the add menu while the caret is inside an alternative, and the closing marker cannot be pushed past the next age-up — an alternative that spans an age boundary is two builds, not one.

Eco graph

Sketch

Drawing both paths doesn't work — every resource series would double and the chart becomes unreadable. So the graph shows one path at a time, picked from the legend. Same selection as the step list: switch in either place and both follow.

Feudal aggressionBooming

The shaded span is the split; outside it the two paths are identical, so that is the only region the two curves differ in.

Switching path redraws the shaded span only — the rest of the chart is unchanged, so the eye stays put. Legend sits under the chart, as it does today.

This is what forces path titles. A series cannot be labelled "the branch" and a condition ("they scout your rush with the scout at 4:00") is far too long for a legend, so each path carries a short title alongside its condition. The title is what the legend, the focus-mode bar and the collapsed row all show.

Nobody declares a main line by default. If an author wants one, it is a main boolean on a path — that path is what the graph opens on. Untouched, the graph opens on the first path.
