Assessment
The card is fine. The chip row is doing the wrong job.
A flag-left horizontal row is the right pattern for this list: strong civ identity, one build per line, scannable, and it survives long titles. Three things hold it back today.
Today — recreated from Builds.vue
Chip soup
Nine chips per card, all the same weight, none of them answering “is this the build I want?”. Views only appear when you sort by views, so the row's content shifts under you.
Proposal
Timings in, chips outRecommended
Age-up times get their own right-hand column, aligned across every row so you can compare builds by scanning straight down. Passive metadata drops to a single quiet line — chips are reserved for things that are actionable (author, creator) or a state (Draft, New). Same card height as today.
Age-up treatments
Three ways to show the timeline
All three read from getTimings(steps) + section age boundaries. They differ in how well they compare across rows.
Honesty
Stated vs. derived
Interpolated timings are estimates and must not look like facts. One rule, applied everywhere: a plain time is one the author stamped; a ~ prefix in lighter type means we derived it from villager deltas. Tooltip on hover: “Estimated from villager count”. No timings at all → the column stays empty, never ??:??.
Light theme
Same structure, navy primary
Age fills use navy for Castle and muted gold for Imperial so the accent still lands on the late ages.
Build details page
Full-width timeline strip
On the details page there is room for the real thing: a shared 0–16:00 track with age markers, villager count at each age-up, and the same stated/derived distinction. Sits directly under the title, above the steps.
xs / sm
Ages replace season and map
On phones the age chips take the slot season/map occupy today — strictly more useful for choosing a build. Author and time stay; everything else waits for the details page.
